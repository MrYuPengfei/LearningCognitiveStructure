# 图片型 PDF 学术名词抽取

把「无文本层的图片型 PDF」转成结构化的中英文术语词表。

## 何时使用

典型触发：用户给出一个装满截图的 PDF 目录，要求提取学术名词、并入既有词表。
判断信号 —— 对目标 PDF 执行 `extract_text()` 后**逐页返回空串或极少字符**，说明它是图片型 PDF，
`pdftotext`/pypdf 这类纯文本方案必然失败，必须走「抽图 + 视觉识别」路线。

不适用：PDF 有正常文本层（直接解析即可，别浪费一轮）；需求是 OCR 整页文字而非抽术语；
图片是散图而非 PDF（直接 Read 图片即可）。

## 核心流程

### 第 1 步：探查并甄别重复源（**不可跳过**）

先跑探查，明确每个 PDF 是图片型还是有文本层：

```bash
python scripts/extract_pages.py <pdf目录> --probe
```

典型输出形如：

```
Snipaste_merged.pdf                    36 页  首页文本    0 字  -> 纯图片(需视觉识别)
snipaste_merged_png.pdf                70 页  首页文本    0 字  -> 纯图片(需视觉识别)
Snipaste_merged_png_2.pdf              68 页  首页文本    0 字  -> 纯图片(需视觉识别)
Snipaste_merged_png_2_compressed.pdf   68 页  首页文本    0 字  -> 纯图片(需视觉识别)
```

**关键判断**：目录里常有同一批内容的多个压缩变体（如 `_compressed`、`_v2`、`_final`），
它们页数相同、内容一致。全量处理等于重复识别、白烧一半算力。
务必逐个核对**页数与生成时间**，只保留每组里的一个代表（通常取最早生成或体积最大的无损版）。

同时检查项目内的历史日志（`.workbuddy/memory/*.md`）与合并脚本，常常已记录这批 PDF 是怎么来的，
能直接省掉甄别过程。

### 第 2 步：抽出页面图片

```bash
python scripts/extract_pages.py <pdf路径> --out <输出目录> --tag A --max-width 1700
```

每页存为 `<输出目录>/<tag>_<页码3位>.jpg`，长边默认压到 1700px。
长边上限是权衡点：太大则子代理识别慢且吃上下文，太小则 PPT 小字看不清，1700 是实测可用值。

多份 PDF 用不同 `--tag`（A/B/C）区分，便于后续追溯词条出处。

### 第 3 步：分批并行派发视觉识别

**不要自己逐张读图**——上百页会把上下文撑爆。正确做法是切成小批、并行派发子代理，
每个子代理用 Read 工具逐张读图，识别完写入一份批次 JSON。

批次大小取 **12~15 张**。低于 10 张浪费并发，高于 20 张单个子代理容易中途丢页。

每个子代理的 prompt 必须包含（照抄第 4 节的抽取规则，不要精简）：
逐张图片的绝对路径清单、输出 JSON 的绝对路径、要求其只回复统计数字而不复述术语。

**同一批中大量图片可能是同一页的重复连拍**（现场录像截屏常见）。
让子代理自行识别并去重，并在回报中说明有几组重复 —— 这是正常现象，不要因此重跑。

批次 JSON 格式：

```json
{"en": ["term1", "term2"], "cn": ["术语1", "术语2"]}
```

### 第 4 步：合并去重并写盘

```bash
python scripts/merge_terms.py --batches <批次目录> --en <英文csv> --cn <中文csv> --dry-run
```

先 `--dry-run` 看统计，确认条数合理（中文材料下英文词条天然偏少，属正常），
再去掉 `--dry-run` 正式写入。脚本是**追加式**的，不会覆盖既有词表。

## 术语抽取规则（派发子代理时逐字带上）

1. 只收**名词性术语**。不要动词、形容词、副词、连接词、完整句子、幻灯片标题短语。
2. 英文保留原始拼写与大小写；缩写必须原样保留（LLM、ReLO、JEV、TPACK、EdNet、System One）。
   普通英文术语可用小写（与既有词表风格一致），但模型名/专有名词保留原样。
3. 中文保留原文，不翻译、不改写。
4. 中英对照出现的同一概念，**英文进 en、中文进 cn，两边都收**。
5. 收录范围：学术理论名、方法名、模型名、概念名、技术名、研究范式、
   心理学与学习科学术语、系统或数据集的专有名称。
6. 不收：纯人名姓氏（但 "Rosenthal effect" 这类整块术语要收）、机构名（知名项目/平台专名除外）、
   日期、数字、流程步骤词（如"第一步"）。
7. 批内去重，保持首次出现顺序。

## 合并阶段的自动清洗（`merge_terms.py` 内置）

1. `clean` — 去 BOM、去首尾标点空白、压缩内部空白。
2. **自动归类** — 按是否含汉字分派，修正子代理放错桶的情况（如 `STEM教育` 误入 en）。
3. 批内去重 — 按小写去重，保留首次出现。
4. 噪声过滤 — 英文剔除纯符号/纯数字/超 70 字符；中文剔除含句读/超 40 字符。
5. 与既有词表按小写去重后**追加**，旧条目顺序完全不变。

## 收尾校验（必做）

写盘后重新读回，确认三个指标：

- 两个文件各自的「行数 == 小写去重后唯一值数」（无重复）
- 英文表无汉字混入、中文表无纯英文混入
- 无超长行、无含句读的条目

用一段 Python 直接算，别靠目测。

## 经验与坑

- **先探文本层再动手**。有文本层的 PDF 走抽图识别是纯粹的浪费。
- **同名不同压缩的 PDF 必须甄别**。这是本流程最大的算力陷阱。
- **词表格式跟随既有文件**。若既有 CSV 是纯文本逐行、无表头无引号，就保持一致，
  不要自作主张加 BOM、加表头或改分隔符。
- **中文为主的材料英文词条会很少**（可能只有 AI、LLM 这类缩写）。
  这是材料本身的属性，不是识别失败，不要为凑数放宽规则。
- 识别结果中夹杂少量生僻或过度切分的词条是正常的。
  严格规则也拦不住子代理的判断偏差，合并后人工扫一眼新增段落即可。
- 项目级工作日志（`.workbuddy/memory/YYYY-MM-DD.md`）记录本次 PDF 的来源关系，
  下次处理同批材料时能直接复用结论。
