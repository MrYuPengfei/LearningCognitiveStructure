# 论文研究笔记写作规范（Note Writing Guide）

本文件是所有论文笔记的写作契约。**每写一篇笔记前必须完整阅读本文件**，并严格照此执行。

---

## 0. 输入与输出

- **输入**：`<库根>\<STEM>_markdown\markdown.md`
  （由 MinerU 解析原始 PDF 得到，含完整正文、LaTeX 公式、图片引用）
  - 少数历史目录的原文文件名为 `<STEM>.md`（而非 `markdown.md`），此时读该文件。
  - 若同目录下还有 `<STEM>.zh.md`（中文译文）与 `<STEM>.en-zh.md`（双语对照），可作为**参考**辅助理解，
    但**公式与数值必须以英文原文 `<STEM>.md` / `markdown.md` 为准**。
- **输出**：`<库根>\<STEM>\<citekey>-<中文译名>.md`
  - cite key 规则（**务必分清两种情形**）：
    1. 若 `<STEM>` 以**字母开头**（如 `Chen2020SimpleDeep-...`、`Kipf2017SemiSupervised-...`），
       cite key = `<STEM>` 第一个连字符 `-` **之前**的部分，即 `Chen2020SimpleDeep`。
    2. 若 `<STEM>` 以**数字开头**（arXiv 编号命名，如 `1609.02907_Kipf-Welling_GCN`），
       则**整个 `<STEM>` 就是 cite key**，不要按连字符截断。
  - 权威来源是 `<库根>/ref.bib`：其中登记的 key 一律是「首个 `-` 之前的部分」，
    且**没有数字开头的条目**——这正是数字开头 STEM 要用完整 STEM 的原因。
  - `<中文译名>` = 本规范模板「一、基本信息」表格中「中文译名」一栏所用的中文标题
    （须与一级标题中的中文译名一致）。
  - ⚠️ **中文译名必须以原文标题为准**。派单时给出的译名仅供参考，可能出错
    （例如把 "Bilateral Reinforcement Learning" 误作「生物启发方法」）。
    **若你读原文后确认译名与派单给定的不一致，以原文为准，并在「一、基本信息」里注明原文标题。**
  - 例：`Anon2025ReasoningAndSampling-推理与采样增强的大语言模型多选题难度预测.md`
  - **不要再写 `README.md`**；每个笔记目录只保留这一个笔记 `.md` 文件。
  - 若 `<STEM>` 以数字开头（如 arXiv 编号 `1609.02907_...`），citation key 取**整个 STEM**（见 AGENT_TASK.md）。
- **图片**：已复制至 `<STEM>\images\`，可直接用相对路径 `images/xxx.jpg` 引用
- **禁止修改**：`_markdown\` 下的任何文件、`middle_json.json` 等解析产物

---

## 1. 语言要求（最高优先级）

1. **正文一律用简体中文**。
2. **学术名词、专业术语、模型名、数据集名、方法名：首次出现时必须在中文后紧跟英文原文，放在小括号里**。
   - 正确示例：`图卷积网络（Graph Convolutional Network, GCN）`
   - 正确示例：`认知卸载（cognitive offloading）`
   - 正确示例：`知识追踪（Knowledge Tracing, KT）`
   - 正确示例：`自调节学习（Self-Regulated Learning, SRL）`
   - 若某术语在文中反复出现，**第一次**给中英对照，之后可只用中文。
3. **公式、数学符号不翻译**，保持原文 LaTeX。变量名、上下标一律保留。
4. **代码、数据集名、指标名、模型名缩写**（如 GCN、GAT、BERT、AUC、RMSE）保留英文。
5. **参考文献条目保留原文**，不要翻译作者名与期刊名。
6. 原文中的**图片说明文字（figure caption）**翻译成中文，但保留英文图号（Figure 1 / Table 2 等）。

---

## 2. 公式要求（最高优先级）

**必须收录论文中的每一个公式，一个都不能遗漏。**

具体要求：

1. **行内公式**用 `$...$`，**独立公式**用 `$$...$$`。
2. 原文公式经 OCR 后常带有多余空格，例如：
   - `H ^ {(i + 1)} = \sigma (\widehat {A} H ^ {(i)} W ^ {(i)})`
   - 应**整理为紧凑规范形式**：`H^{(i+1)} = \sigma\left(\widehat{A} H^{(i)} W^{(i)}\right)`
3. **保留原文的编号**（如 `\tag{1}`、`\tag{2}`），写在公式末尾。
4. **必须给出公式中每个符号的含义**（哪些是矩阵、维度、激活函数、可学习参数等）。
5. **定理、引理、定义、证明中出现的公式也要全部收录**，证明过程要用中文复述其推导逻辑，不能只丢一个公式。
6. **算法伪代码**用代码块收录，变量名保留原文。
7. 论文最后要有**「附录 A：全文公式汇总」表格**，把所有公式按出现顺序列出（编号 / 公式 / 含义）。
8. 若某公式原文是图片形式（MinerU 未能识别为 LaTeX，只存成了 jpg），在公式汇总表中注明"见图片"，并给出图片路径。

### 2.1 重要：MinerU 会导出未被正文引用的公式切图

MinerU 在 `images/` 目录里会额外导出 `page_N_equation_M.jpg`（公式切图）和
`page_N_table_M.jpg`（表格截图），但**这些图片在 `markdown.md` 正文中没有 `![]()` 引用**。

实测全库：**372 个目录、6226 张图片未被引用，其中 4218 张是公式切图（67%）、1980 张是表格截图（31%）**。

因此：
- **不要只依赖 markdown.md 的图片引用来判断「原文有没有这张图」**。
- 写附录 A（公式汇总）时，应主动到 `images/` 里找 `*_equation_*.jpg`，
  它们是公式的**视觉证据**，可用于核对 LaTeX 转写是否正确（用 Read 工具看图）。
- 若某条公式在 `images/` 中有对应的 `equation_*.jpg`，在汇总表的「图片路径」列填上，
  使读者能逐条核对；正文则可选择性地在公式旁插入 `![](images/xxx_equation_N.jpg)`。
- 附录 B（图表索引）同理，应把 `images/` 下实际存在的表格/图表截图一并登记。
- 伪代码（Algorithm/Code N）在 `markdown.md` 里往往**只有文字、没有图片引用**，
  但 `images/` 里可能有对应切图，也要一并查找。

## 3. 内容详尽度要求

笔记必须**详尽**，目标是让读者**不读原文也能完整复现论文的方法与结论**。

必须覆盖：

| 维度 | 要求 |
| --- | --- |
| 问题动机 | 作者想解决什么？现有方法为什么不行？（要有具体例子/反例） |
| 记号体系 | 所有数学记号的定义，逐个说明 |
| 方法细节 | 模型结构、每层/每模块的作用、为什么这样设计 |
| 理论分析 | 定理、引理、定义的**完整陈述 + 证明思路/完整推导** |
| 复杂度 | 时间/空间复杂度分析（若有） |
| 实验设置 | 数据集（规模、划分方式）、基线、超参数、训练细节、评测指标 |
| 实验结果 | 关键数字要**逐项列出表格**，不要只说"效果更好" |
| 消融实验 | 若有，逐项说明每个消融的结论 |
| 贡献 | 逐条列出作者声明的贡献 |
| 局限 | 原文自述的局限 + 你的批判性评价 |
| 相关工作 | 与已有方法的区别（要具体对比，不是罗列） |

---

## 4. 标准章节结构（固定模板）

```markdown
# 研究笔记：<中文译名>（<English Title>）

> 本笔记由 MinerU 解析原始 PDF 后整理，公式均按原文逐条收录。

## 一、基本信息（Basic Information）
（表格：英文标题 / 中文译名 / 作者 / 机构 / 发表 venue 与年份 / 代码链接 / 任务 / 关键词）

## 二、一句话概括（One-sentence Summary）
（1-3 句话，说清"做了什么 + 为什么 + 结果如何"）

## 三、研究问题与动机（Problem and Motivation）
（背景、现有方法的缺陷、本文要解决的问题；有具体例子必须写出）

## 四、记号与预备知识（Notation and Preliminaries）
（所有符号定义、相关基础方法回顾）

## 五、方法：<方法名>（Proposed Method）
（模型结构、核心公式、模块说明、复杂度分析、算法伪代码）

## 六、理论分析（Theoretical Analysis）
（定义 / 定理 / 引理 / 证明。没有就删掉此节）

## 七、实验设计（Experimental Design）
（假设、数据集、基线、超参数、训练细节、评测指标）

## 八、实验结果（Experimental Results）
（主结果表、消融表、可视化分析，逐项列出数字并解释）

## 九、相关工作（Related Work）
（与已有方法的**具体**区别）

## 十、结论（Conclusion）

## 十一、批判性评价与启发（Critical Appraisal）
### 11.1 优点
### 11.2 局限与可质疑之处
### 11.3 与本课题（Fusion 项目）的关联
（此处填写你所在课题的背景与关切点，让笔记能把论文挂回自己的研究脉络。
延伸思考请明确标注"以下为笔记撰写者的延伸思考，非原文内容"。）

## 附录 A：全文公式汇总（Formula Index）
（表格：编号 / 公式 / 含义）

## 附录 B：图表索引（Figure & Table Index）
（表格：编号 / 内容 / 文件路径）
```

**灵活性**：若论文没有理论分析，删掉第六节；若是综述论文，把"方法"改为"综述框架与分类体系"；若是短论文，相应精简但**公式必须全部保留**。结构可调整，但**详尽度与公式完整性不可打折**。

---

## 5. 图片引用

- 用 `![中文图注](images/page_1_image_body_0.jpg)` 的形式插入。
- **只引用确实存在的文件**（从 markdown.md 里的 `![](images/...)` 提取）。
- 图注写成：`图 N：<中文说明>`。
- 表格若原文是图片，也用图片引用，并在正文里**把表格内容以 Markdown 表格重排**（若 MinerU 已抽出 Markdown 表格则直接保留）。

---

## 6. 质量红线

1. **不得编造**：数字、引用、实验结果必须与原文一致。不确定就写"原文未明确说明"。
2. **不得遗漏公式**：这是硬性要求。
3. **不得只写摘要式概括**：要展开方法细节与推导。
4. **不得整段照抄英文原文**：必须用自己的中文复述。
5. **表格数字要对齐**：用 Markdown 表格，保留原文的 ± 标准差。
6. 长度：**不设上限**，宁详勿略。典型篇幅 4000–12000 字。

---

## 7. 排版细节

- 一级标题用 `##`，二级用 `###`，与模板一致。
- 每个二级标题后紧跟英文对照括号。
- 重要结论用**加粗**。
- 公式与正文之间留空行，保证渲染正确。
- 文件末尾不写"以上"之类收尾客套话。
