# Methodology — 5 阶段详细执行手册

5 阶段是流程主干。本文件给出**每个阶段的具体问题脚本**和**输出模板**，WorkBuddy 应按此推进。

---

## §1. 确认范围与交付物（前置，不到 5 分钟）

### 必问的问题
1. 您想萃取的**课题**是什么？例如：销售拜访 / 客户挽回 / 新员工入职 / 项目复盘 / 投诉处理。
2. 这是**谁的**经验？岗位 + 资历（例如：3 年以上的一线客户经理）。
3. 产出物想要**什么形式**？分支：
   - **SOP / 操作手册**（给执行者照着做）
   - **培训课程 / 课纲**（给学员学）
   - **案例**（STAR / 高峰体验，给别人读）
   - **方法论模型**（公式 / 口诀 / 矩阵，给团队传播）
4. 计划的**应用场景**？培训新人 / 复制优秀经验 / 标准化作业。

### 输出
```
- 课题：[一句话]
- 萃取对象：[岗位 + 资历]
- 交付物形式：[SOP / 课程 / 案例 / 模型]
- 应用场景：[培训新人 / 复制 / 标准化]
```

---

## §2. Stage 1 — 任务拆解

### 必问的问题
1. 这个岗位上的人，**最核心要做的事**是什么？（一级任务）
2. 每个一级任务可以**再拆成几步**？（二级任务）
3. 拆完后，是否**加起来 = 这个岗位的全部职责**？是否**彼此不重叠**？

### 拆解规则（MECE + 动宾结构）
- 每个任务用 **动宾结构**：动词 + 宾语。例：拜访客户（√）、客户（×）。
- 字数 ≤ 10 个字。能再加细节。
- 二级任务 ≥ 5 条，**且互不重复**。
- 颗粒度对齐：避免"接到订单"和"维护客户"这种粒度悬殊的并列。

### 输出模板
```
一级任务 A1：[名称]
  二级任务 A1-1：[动宾]
  二级任务 A1-2：[动宾]
  ...
一级任务 A2：[名称]
  ...
```

### 推进信号
用户给出 ≥ 5 条二级任务、动宾结构 OK、与课题相关 → 进入 Stage 2。

---

## §3. Stage 2 — 三点深挖（难点 / 痛点 / 关键点）

### 必问的问题（对每个二级任务问一遍）
- **难点**：哪一步是**最复杂**的？需要思考、判断或多方协调？
- **痛点**：哪一步**最让人难受**？哪里反复卡住 / 容易出错？
- **关键点**：哪一步**做不好后果最严重**？必须做对否则后续崩盘？

### "三点"含义辨析
- **难点 = 复杂环节**（脑力 / 学习门槛）
- **痛点 = 直接障碍**（执行中反复遇到的麻烦）
- **关键点 = 易出错且后果大的环节**（新手最容易栽的坑）

三者**经常重合但不必然相同**——这正是后续萃取的入口。

### 输出模板
```
任务编号 | 任务名 | 难点 | 痛点 | 关键点
A1-1    | 拜访准备 | 收集客户画像 | 不知道该问什么 | 没准备好就被客户带偏
A1-2    | 面谈开场 | 30 秒破冰 | 客户冷淡不配合 | 开场不好后面全废
...
```

### 推进信号
对每一行任务都填满了"三点"（哪怕填一句简短描述也行）→ 进入 Stage 3。

---

## §4. Stage 3 — 经验萃取

### 显隐分流（必须先判断）
- **显性经验**：用户能说清楚"我做了什么 / 用什么 / 按什么步骤"。
  → 追问：**What**（这件事是什么）+ **How**（怎么做、什么顺序、用什么工具）。
- **隐性经验**：用户说"凭感觉 / 看情况 / 看客户反应"。
  → 追问：**Magic-wand 法**（"如果我给你一根魔法棒，最希望改变/做到什么？"）+ **STAR 还原**：当时的情境 / 任务 / 行动 / 结果 / 你当时的思考。
  → 必要时做 **高峰访谈**：还原 1-2 次最成功或最失败的案例，逐句追问"当时你怎么想的 / 你怎么判断 / 你看到什么信号"。

### 关键问题清单（隐性经验专用 — "高峰访谈 6 问"）
1. 当时是什么情境？（背景）
2. 你面临的最大挑战是什么？（挑战）
3. 你心里的**想法**是什么？（想法 vs 做法经常不同！）
4. 你说了什么、做了什么？（说法 + 做法）
5. 关键措施是哪一步？（关键点）
6. 事后你怎么**优化**它？（复盘）

### 萃取深度三档
- **做了**：按流程做完，但未必到位。
- **做好**：满足标准，关键节点控制好。
- **做到极致**：超出预期，有不可复制的"手感"。

萃取的最终目标是**第三档**——把"手法"挖出来。

### 案例数量与验证规则（用户经验，务必执行）

单案例容易把"偶然做法"当成"方法论"。进 Stage 4 之前，按以下顺序增加案例：

1. **多举 1-2 个正面案例**：请用户再讲 1-2 个"做法类似"的经历，验证首次案例里的动作**是否每次都这么做**。
   - 多案例一致 → 方法论扎实；
   - 多案例不一致 → 恰恰是最有价值的差异点，追问"这两次为什么不一样？"
2. **1 个反面案例**：请用户讲 1 次"同样场景但搞砸了 / 没这么做结果翻车"的经历，验证方法论的**边界**（什么时候会失效）。
   - 反例对照正面案例 → 能提炼出"坑"和"适用条件"。
3. **举不出来也没关系**——但必须告知用户一句：
   > "案例越多，萃取的越扎实。多一个案例，模型就更接近真相一分。"
   
   然后按现有材料推进，不硬凑。

### 无案例兜底：转为"日常操作描述"（用户经验，务必执行）

**不是所有经验都长在"案例"上。** 有些课题本身就是**操作性 / 流程性**的——例如"如何做一个体系规划""如何设计一个方案""如何搭建指标体系""如何做年度培训计划"。这类经验的持有者很可能**一时想不出具体案例**，这不是没经验，而是经验以"做法"而非"事件"的形式存在。**不要把"想不出案例"误判为"没经验"。**

只要用户答不出案例，就立刻切到下面这条兜底问法：

1. **先给台阶，别让对方卡在"想不起来"上**：
   > "一时想不起具体案例也没关系。那换个问法——**如果没有实际案例，就描述一下你日常都是如何开展这项工作的？**"
2. **把"案例问法"换成"流程问法"**（一层层往下问，一次只问一层）：
   - "这件事一般你从哪一步开始？"
   - "平时做一次，大概走哪几步？"
   - "有没有固定的模板 / 框架 / 清单 / 表格？"
   - "哪些地方你每次都会特别注意？"
   - "做到什么程度，你才觉得可以交付了？"
3. **从"日常做法"倒推"具体画面"**：用户描述完流程后，再帮他把最近一次操作在脑中走一遍——
   > "就按你刚说的流程，回忆最近一次做的时候，哪一步最花时间 / 最费脑？"
   这一步往往能把"流程描述"重新变回"案例素材"。
4. **效果不打折，反思三问照走**（问法微调即可）：
   - ① 成功关键点 → "你觉得这套做法里，最关键的是哪一步？"
   - ② 待改进点 → "如果再优化一次，你会改哪里？"
   - ③ 挑战 + 备选 → "这套做法最怕遇到什么情况？除了现在这样，还能怎么应对？"

> **判定要点**：**案例型经验** → 用 STAR / 高峰访谈挖事件；**操作型经验** → 用"日常流程描述 + 步骤复盘"挖做法。两者产出物**同等有效**，只是入口不同。很多"方法论型"高手属于后者——他们很难举出一次具体经历，但能把做法讲得极清楚。

### 案例反思三问（用户经验，务必执行）

**在问完一个案例之后**（描述完经过还不算完），必须补问这 3 个问题——它们把萃取从"复述经历"推进到"反思经历"，是"做了 → 做好 → 做到极致"的跃迁入口。

1. **成功的关键点是什么？**（自我反思成功要素）
   - 追问目的：让用户自己**归因**。做了什么 ≠ 为什么成。用户自己说出的"关键点"，往往就是他方法论的**道与法**。
   - 追问话术："回头看，这次能成，最关键的是一点还是几点？哪一点少了就不行了？"
   - 输出：该案例的**成功要素清单**（用于 Stage 4 找共性）。

2. **如果再做一遍，哪里需要改进？**（找改进空间）
   - 追问目的：挖出**优化点**和**坑**。完美复述的案例里藏着刻意被忽略的遗憾。
   - 追问话术："如果时间倒流再走一遍，哪个环节您一定会改？怎么改？"
   - 输出：该案例的**改进点 / 坑位清单**（可直接进 SOP 的"坑"层）。

3. **过程中最挑战的是什么？除了这个案例中的做法，还可以采取哪些举措应对？**（挑战 + 替代方案）
   - 追问目的：① 识别**真正的瓶颈**（挑战 = 这套打法的压力测试点）；② **扩展招式库**——同一挑战用户可能有多条备选路径，只挖一条就会造成"路径依赖"。
   - 追问话术："最挑战的是哪一步？除了您这次用的办法，还能怎么应对？还有别的招吗？"
   - 输出：**挑战 → 备选举措**对照表（一个挑战配 2-3 种打法，SOP 里可写主用招 + 备用招）。

> **执行要点**
> - 每个核心案例（尤其是主案例与反例）都要走一遍这三问；案例多时可对最关键 1-2 个案例深问。
> - 三问是**提问**，不是让 AI 自答——依然遵守"提问引导，不替用户断言"的总规则。
> - 第三问的"还可以采取哪些举措"是**扩量器**：用户若只答得出 1 种，可轻推一句"还有别的思路吗？别人会怎么做？"，但**不硬凑**，没有就按已有材料推进。

### 实物资产采集：模板 / 工具 / 表单（用户经验，务必执行）

**要的不仅是"脑子里的做法"，还有"手上现成的资产"。** 模板、工具、表单、清单、话术卡、检查表——这些是**已经沉淀过的显性知识**，属于"器"层最硬的素材，也是新人拿到就能用的东西。萃取时如果只收集口头描述、不收集这些资产，等于把**最容易复用的那部分**丢掉了。

**何时问：**
- 用户只要提到"我们有固定的表 / 通常填个单子 / 有个模板 / 有个工具" → **立刻顺势要**，别放过；
- Stage 3 收尾（案例 + 反思三问之后）**必问一次**，作为兜底动作。

**怎么问（直接用这几句）：**
> "做这件事，您平时有没有现成的**模板 / 工具 / 表单 / 清单**？如果有，**直接粘进来**——这是萃取成果里最有价值的部分之一，新人拿到就能用。"
>
> 若对方说"有，但很粗" → "粗也没关系，先粘过来，我们一起看它为什么这么设计。"

**收到之后怎么用（三步加工，不要只是收录）：**

1. **直接入库为交付物的"器"层 / 附录**
   - 模板 / 表单原文进 SOP 或课纲的附件，标注"**可直接复用**"。
   - 交付物里区分两类：**可直接拿走用**（模板本身）vs **需要理解才能用**（背后的判断标准）。

2. **模板解剖 —— 反推隐性判断（这一步最值钱）**
   模板上的每一栏，都暴露了使用者的**关注要素**；栏目的顺序，往往就是**流程的顺序**。逐栏追问：
   - "这一栏为什么要填？不填会怎样？"
   - "这一栏您一般怎么判断？填成什么样算好？"
   - "顺序为什么这么排？"
   → 把**显性的表单**反向挖出**隐性的判断标准**，直接补进"术"层。

3. **判断可直接沿用 or 需要升级**
   - 现成模板 → 直接沿用（标注来源）；
   - 有明显缺项的 → 交付物里标"建议增补 XX 栏"，但**先说清原设计意图**再谈改进，别一上来就否定用户多年的东西。

**兜底：对方说"没有模板"怎么办？**
- 不必尴尬，这正是机会 —— "那太好了，我们正好可以把它做出来。"
- 但**不要 AI 凭空造**：基于用户已有的口头描述（Stage 3 攒下的素材）**反向生成**一版草案，交用户改。内容是用户的，形态是 AI 的工艺（与 Stage 4 多候选原则一致）。

> **判定要点**：问"有没有模板"是**低门槛高回报**的一问——对方答"有"就白得一份现成资产；答"没有"也顺势引出了下一个交付物。任何时候都值得问。

### 输出模板（按任务分组）
```
任务 A1-1（拜访准备）的萃取结果：
- 显性做法：[列出 What + How]
- 隐性手法：[包含魔法棒答案、高峰访谈还原的判断 / 信号]
- 案例：[STAR 简述]
- 反思三问：
    · 成功关键点：[用户自述的归因]
    · 待改进点 / 坑：[用户自述的改进空间]
    · 最大挑战 + 备选举措：[挑战是什么] → [举措1 / 举措2 / 举措3]
- 实物资产：[模板 / 表单 / 工具 / 清单 —— 原文或要点（含"可直接复用"标注）]
    · 模板解剖：[每栏为什么填 / 怎么判断 / 顺序逻辑] → 反推出的隐性标准
```

### 推进信号
每个核心任务的"显性 + 隐性 + 案例 + **反思三问** + **实物资产（有则收，无则标注'待生成'）**"都齐全 → 进入 Stage 4。

## §5. Stage 4 — 模型构建

### 选择 8 种建模法之一
详见 `model-builder.md`。

简版选择：
- **公式**法（X = A + B + C）— 适合工具组合型
- **二维矩阵**（2×2 / 3×3）— 适合两个对立维度
- **层次法**（金字塔 / 漏斗）— 适合分阶段流程
- **排比法**（三个以上的并列项）— 适合价值观 / 原则
- **简写词**（首字母组合）— 适合步骤 / 框架命名
- **英文字母**（如 PDCA / STAR）— 类似简写，但用外文字母
- **口诀 / 顺口溜** — 适合传播、易记
- **三字经**（三字一句） — 适合文化型传播

### "5 步成模"
无论选哪种建模法，请按这 5 步迭代：
1. **找共性**：跨多个任务的共同做法是什么？
2. **看差异**：高手 vs 普通人的分水岭在哪？
3. **挖实质**：差异背后的根本原因是什么？
4. **要拔高**：用一句让人记住的话总结。
5. **成模型**：用上面 8 种之一表达出来。

### 多候选呈现（必做 — 详见 model-builder.md 总则）
访谈完成后，AI 用 **2-3 种不同建模法**（如简写词法 / 公式法 / 英文字母法 / 口诀法）把**同一份用户素材**各翻译成一个候选模型，并排展示让用户挑选、修改或组合。内容必须全部来自用户素材，AI 不引入新观点。

### 推进信号
用户能用自己的话说出"我做的这件事能用 X 模型概括" → 进入 Stage 5。

## 通用收尾：复盘三问
1. 这份萃取出来的方法论，能**让一个新人用 30 天达到现有高手的水平**吗？
2. 哪些环节**仍然依赖手感**没被结构化？
3. 这些"手感"下一步如何继续萃取？（答：是下一轮萃取的输入）
